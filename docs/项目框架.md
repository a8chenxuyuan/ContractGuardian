# 合同卫士 — 项目框架介绍

> 本文档介绍项目的整体框架，说明每个目录和关键文件的作用，帮助新人快速定位代码。

---

## 一、项目整体框架

合同卫士项目由三大部分组成：

```text
contract-guard/                  # 项目根目录
├── docs/                        # 文档
├── frontend/                    # 前端（Vue3 + TypeScript）
├── backend/                     # 后端（FastAPI + Python）
├── pg/                          # PostgreSQL 本地运行目录（基础设施）
├── qdrant/                      # Qdrant 本地运行目录（基础设施）
├── storage/                     # Qdrant 向量数据（运行时生成）
├── .gitignore                   # Git 忽略规则
└── .qdrant-initialized          # Qdrant 初始化标记
```

| 目录/文件 | 作用 |
|-----------|------|
| `docs/` | 项目文档，包含计划、设计、逻辑说明、问题记录 |
| `frontend/` | 前端工程，用户看到的界面 |
| `backend/` | 后端工程，提供 API、解析文档、运行 Agent、管理数据 |
| `pg/` | PostgreSQL 数据库二进制文件和数据文件 |
| `qdrant/` | Qdrant 向量数据库可执行文件 |
| `storage/` | Qdrant 运行时生成的向量数据和索引 |
| `.gitignore` | 规定哪些文件不应提交到 Git |
| `.qdrant-initialized` | Qdrant 首次初始化后生成的标记文件 |

### 2.1 源码目录 `src/`

| 文件/目录 | 作用 |
|-----------|------|
| `main.ts` | 前端入口，创建 Vue 应用实例，挂载到 DOM |
| `App.vue` | 根组件，定义整体布局（如导航栏、路由视图容器） |
| `views/` | 页面级组件，每个文件对应一个页面 |
| `components/` | 可复用组件，供多个页面调用 |
| `api/` | 封装 Axios 请求，统一调用后端接口 |
| `router/index.ts` | Vue Router 路由表，定义 URL 与页面对应关系 |
| `stores/` | Pinia 状态管理，如登录状态、用户信息 |
| `types/index.ts` | TypeScript 类型定义，如 User、Contract、Finding |

### 2.2 页面组件 `src/views/`

| 文件 | 页面 | 功能 |

| 说明 |

#### 3.2.1 Agent 实现 `app/review/agents/`

当前 `app/review/agents/` 下共 **15 个 Agent 类**：1 个抽象基类 `BaseAgent`（基类文件位于 `app/agentkit/base.py`）+ 14 个可运行的内置 Agent。

| 文件 | Agent | 职责 |
|------|-------|------|
| `app/agentkit/base.py` | BaseAgent | 抽象基类，定义 ReAct 循环、工具调用、LLM 交互、进度发布 |
| `term_extraction.py` | TermExtractionAgent | 提取合同关键商务条款 |
| `risk_review.py` | RiskReviewAgent | 识别不公平/高风险条款，内置 RedFlagDetector 红线扫描与 CriticAgent 二次校验 |
| `legal_research.py` | LegalResearchAgent | 动态推断适用法律领域，检索法条并生成审查要点 |
| `missing_clause.py` | MissingClauseAgent | 检查必要条款缺失 |
| `balance.py` | BalanceAgent | 分析双方权利义务对等性 |
| `cross_reference.py` | CrossReferenceAgent | 检查前后条款引用一致性 |
| `legal_basis.py` | LegalBasisAgent | 为风险匹配法律依据 |
| `suggestion.py` | SuggestionAgent | 生成具体修改建议 |
| `industry_compliance.py` | IndustryComplianceAgent | 行业特殊合规检查 |
| `legal_verify.py` | LegalVerifyAgent | 验证法条引用准确性 |
| `debate.py` | DebateAgent | 对高风险项进行正反辩论 |
| `blind_spot.py` | BlindSpotAgent | 扫描容易被忽略的盲区 |
| `human_review.py` | HumanReviewAgent | 标记需要人工复核的项 |
| `chat.py` | ChatAgent | 基于合同内容回答用户问题 |
| `critic.py` | CriticAgent | 对 RiskReviewAgent 的候选风险做 RuleCritic + LLM Critic 二次校验，降低误报 |

## 七、总结

- **前端**负责用户界面：上传、展示进度、查看报告、对话。
- **后端**负责业务逻辑：API、解析文档、管理数据、协调 Agent。
- **Agent 系统**负责智能审查：多个专业 Agent 并行工作，在 SessionGraph 上共享信息。
- **基础设施**负责存储和检索：PostgreSQL 存关系数据，Qdrant 存向量，Redis 做消息广播和任务队列。
- **文档**记录项目背景、计划、逻辑和问题，方便团队协作。
